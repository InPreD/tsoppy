# Metrics plots

The `metric-plots` subcommand processes TSO500 `MetricsOutput.tsv` files and creates standardized metrics tables for downstream QC plotting.

The command supports metrics generated by different workflows, including DRAGEN and LocalApp. Workflow type and workflow version are determined from the workflow output rather than specified manually by the user.

## Input

The command requires an input directory containing the workflow outputs to be processed.

Run IDs can be provided in either of two ways:

- as a comma-separated list using `--run-ids`
- in a text file using `--run-id-file`

Both options can also be used together. Duplicate run IDs are removed automatically.

### Run IDs from the command line

```bash
tsoppy metric-plots \
    --input-directory /path/to/workflow/results \
    --run-ids RUN_001,RUN_002,RUN_003
````

### Run IDs from a text file

The run ID file contains one run ID per line:

```text
RUN_001
RUN_002
RUN_003
```

Run the command with:

```bash
tsoppy metric-plots \
    --input-directory /path/to/workflow/results \
    --run-id-file /path/to/run_ids.txt
```

### Combining both input methods

Run IDs supplied using both options are combined:

```bash
tsoppy metric-plots \
    --input-directory /path/to/workflow/results \
    --run-ids RUN_001,RUN_002 \
    --run-id-file /path/to/additional_run_ids.txt
```

## Output

By default, output files are written to the current working directory.

A different working directory can be specified using `--workdir`:

```bash
tsoppy metric-plots \
    --input-directory /path/to/workflow/results \
    --run-id-file /path/to/run_ids.txt \
    --workdir /path/to/workdir
```

The command produces:

```text
master_metrics_table.tsv
joint_sequencing_QC_file.tsv
```

### Master metrics table

`master_metrics_table.tsv` contains the QC metrics collected from the selected workflow outputs.

The table includes metadata columns such as:

```text
SAMPLE_ID
RUN
WORKFLOW_TYPE
WORKFLOW_VERSION
RECORD_TYPE
```

Metric columns are organized so that:

* run-level metrics have no DNA/RNA prefix
* DNA-specific metrics use the `DNA_` prefix
* RNA-specific metrics use the `RNA_` prefix

`RECORD_TYPE` distinguishes different types of rows, including:

```text
DNA_SAMPLE
RNA_SAMPLE
LOWER_THRESHOLD
UPPER_THRESHOLD
```

The lower and upper threshold rows contain the recommended LSL and USL values reported in the workflow metrics files.

Because `WORKFLOW_TYPE` and `WORKFLOW_VERSION` are stored explicitly, the same master table can contain data generated by different workflow versions.

Care should be taken when comparing metrics between workflows because metrics with the same name may have been calculated or reported differently by different workflow versions.

### Joint sequencing QC table

`joint_sequencing_QC_file.tsv` contains run-level sequencing QC metrics used for downstream QC reporting.

Examples include:

```text
PCT_PF_READS
PCT_Q30_R1
PCT_Q30_R2
CLUSTER_DENSITY
ESTIMATED_YIELD
CLUSTERS_PASSING_FILTER
```

Run-level values remain associated with their workflow type and workflow version.

## Selecting runs for plotting

The metrics module can also prepare a Polars dataframe containing only the runs that should be passed to the downstream Python QC plotting module.

The filtering is performed in memory; an additional intermediate TSV file is not created.

### Plot the most recent runs

To select the last eight run IDs from the generated master table:

```bash
tsoppy metric-plots \
    --input-directory /path/to/workflow/results \
    --run-id-file /path/to/run_ids.txt \
    --plot-last-runs 8
```

The order is based on the run order in the master metrics table.

All rows associated with the selected runs are retained, including their:

* sample rows
* workflow type
* workflow version
* lower thresholds
* upper thresholds

### Plot specific runs

Specific runs can instead be selected using a comma-separated list:

```bash
tsoppy metric-plots \
    --input-directory /path/to/workflow/results \
    --run-id-file /path/to/run_ids.txt \
    --plot-run-ids RUN_002,RUN_005,RUN_009
```

`--plot-last-runs` and `--plot-run-ids` are mutually exclusive.

## Plotting integration

The metrics processing and plotting responsibilities are intentionally separated.

The processing flow is:

```text
Workflow output
      |
      v
MetricsOutput.tsv
      |
      v
MetricsOutputTsv
      |
      v
MetricPlots
      |
      +--> master_metrics_table.tsv
      |
      +--> joint_sequencing_QC_file.tsv
      |
      +--> filtered Polars dataframe
                 |
                 v
          Python QC plotting
```

`MetricsOutputTsv` is responsible for representing and parsing a workflow's `MetricsOutput.tsv`.

`MetricPlots` reformats the parsed sections into standardized metrics data.

The selected plotting dataframe can then be passed directly to the Python QC plotting module without writing and rereading a temporary intermediate file.

## Help

The available options can always be inspected with:

```bash
tsoppy metric-plots --help
```
